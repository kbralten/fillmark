# Fillmark — Public Release Readiness Evaluation

## 1. Functional, Security & Reliability Bugs (Fix Before Public Launch)

### Health Connect Sync Reliability
- **Background inbound sync triggers `SecurityException` and wipes the changes token:** [HealthConnectManager.kt](file:///c:/Users/kevin/Dev/fillmark/app/src/main/kotlin/com/fillmark/app/sync/HealthConnectManager.kt#L37-L50) schedules [HealthConnectSyncWorker.kt](file:///c:/Users/kevin/Dev/fillmark/app/src/main/kotlin/com/fillmark/app/sync/HealthConnectSyncWorker.kt#L35-L38) every 15 minutes in the background, where it calls `syncInbound()` (`client.getChanges()`). Android Health Connect rejects background reads unless `android.permission.health.READ_HEALTH_DATA_IN_BACKGROUND` is declared and granted (it is not declared in [AndroidManifest.xml](file:///c:/Users/kevin/Dev/fillmark/app/src/main/AndroidManifest.xml#L5-L7)). When `SecurityException` is thrown, [HealthConnectManager.kt](file:///c:/Users/kevin/Dev/fillmark/app/src/main/kotlin/com/fillmark/app/sync/HealthConnectManager.kt#L301-L304) catches `Exception` and **resets the changes token to `null`**, causing repeated 30-day backfills and silently dropping upstream `DeletionChange` events. Meanwhile, `HealthConnectSyncWorker` still updates `lastHealthConnectSyncMillis` to "now" and returns `Result.success()` instead of retrying transient errors.
  - *Fix:* Run inbound sync only in the foreground (on resume / "Sync Now") to avoid Play Console's stricter background-read review (or explicitly declare/request `READ_HEALTH_DATA_IN_BACKGROUND`), never wipe the changes token on `SecurityException`, and only advance `lastHealthConnectSyncMillis` on successful sync.
- **Granular Health Connect permissions break outbound-only sync:** [HealthConnectManager.kt](file:///c:/Users/kevin/Dev/fillmark/app/src/main/kotlin/com/fillmark/app/sync/HealthConnectManager.kt#L98-L115) checks `hasAllPermissions()` (both `READ_HYDRATION` and `WRITE_HYDRATION`) for every operation. If a user grants Write but denies Read (wanting outbound-only sync), outbound sync stops working entirely and Settings reports permissions as missing. Split into `hasWritePermission()` and `hasReadPermission()`.
- **Best-effort deletes can orphan records in Health Connect:** [HydrationRepository.kt](file:///c:/Users/kevin/Dev/fillmark/app/src/main/kotlin/com/fillmark/app/data/repository/HydrationRepository.kt#L142-L151) attempts an inline `hcManager.deleteRecord()` and swallows exceptions without a retry queue/tombstone, so transient failures permanently leave deleted entries in Health Connect.

### Home Screen Widgets & Splash Screen
- **Widget "30-second Undo" chip gets stuck on the home screen:** [QuickLogBarWidget.kt](file:///c:/Users/kevin/Dev/fillmark/app/src/main/kotlin/com/fillmark/app/widget/QuickLogBarWidget.kt#L66-L67) and [FullDashboardWidget.kt](file:///c:/Users/kevin/Dev/fillmark/app/src/main/kotlin/com/fillmark/app/widget/FullDashboardWidget.kt#L147-L148) evaluate `canUndo = ... <= 30_000L` once during composition, but nothing triggers a widget refresh 30 seconds later (`QuickLogBarWidget` has no timer; `FullDashboardWidget` only emits state changes when `LocalDate` changes). As a result, the Undo button stays stuck indefinitely (also hiding the 5th preset in `QuickLogBarWidget`) until the next widget update. In addition, [UndoWidgetLogActionCallback](file:///c:/Users/kevin/Dev/fillmark/app/src/main/kotlin/com/fillmark/app/widget/WidgetActionCallback.kt#L72-L92) does not enforce the 30-second window before deleting the record.

- **Light-mode Splash Screen icon is nearly invisible:** [themes.xml](file:///c:/Users/kevin/Dev/fillmark/app/src/main/res/values/themes.xml#L7-L11) renders `@drawable/ic_launcher_foreground` directly on `#F6F9FB` (near-white). Because [ic_launcher_foreground.xml](file:///c:/Users/kevin/Dev/fillmark/app/src/main/res/drawable/ic_launcher_foreground.xml#L26-L84) draws a white outline, translucent white body (`#4DFFFFFF`), and light cyan cap (designed for the dark teal adaptive icon background), the upper half of the bottle disappears on light-mode launch. Use a dedicated high-contrast splash drawable (or set a dark splash background / API 31+ `windowSplashScreenIconBackgroundColor`).

### Data Integrity, Settings & Security
- **JSON backup restore lacks validation and can duplicate Health Connect records:**
  - [BackupManager.decodeBackupJson](file:///c:/Users/kevin/Dev/fillmark/app/src/main/kotlin/com/fillmark/app/data/backup/BackupManager.kt#L94-L98) accepts any `schemaVersion >= 1` (including future unknown schemas) and does not validate imported fields (negative/NaN/infinite volumes, invalid `hydrationFactor`, blank IDs, malformed `HH:mm` waking hours, or invalid dates).
  - [BackupManager.restoreBackupFromUri](file:///c:/Users/kevin/Dev/fillmark/app/src/main/kotlin/com/fillmark/app/data/backup/BackupManager.kt#L202-L214) clears `healthConnectId` and sets `lastSynced = 0L` without resetting the Health Connect changes token or pausing sync — if Health Connect is enabled, the next sync will re-upload every restored record, duplicating existing Health Connect entries.
- **`clearAllData()` is non-transactional and leaves periodic sync running:** [HydrationRepository.clearAllData](file:///c:/Users/kevin/Dev/fillmark/app/src/main/kotlin/com/fillmark/app/data/repository/HydrationRepository.kt#L178-L184) performs separate DAO deletes/inserts outside `database.withTransaction`, and [SettingsViewModel.clearAllData](file:///c:/Users/kevin/Dev/fillmark/app/src/main/kotlin/com/fillmark/app/ui/settings/SettingsViewModel.kt#L229-L243) does not cancel scheduled Health Connect periodic WorkManager jobs.
- **Settings daily target field goes stale after restore/reset and writes on every keystroke:**
  - [SettingsScreen.kt](file:///c:/Users/kevin/Dev/fillmark/app/src/main/kotlin/com/fillmark/app/ui/settings/SettingsScreen.kt#L146-L154) only refreshes `targetInput` when `displayUnit` or `hasTarget` changes, leaving a stale number displayed after JSON restore or Clear Local Data.
  - [SettingsScreen.kt](file:///c:/Users/kevin/Dev/fillmark/app/src/main/kotlin/com/fillmark/app/ui/settings/SettingsScreen.kt#L336-L346) calls `updateDailyTargetPreservingHistory()` on **every single keystroke**, repeatedly hitting Room, DataStore, and `WidgetUpdateHelper.updateAllWidgets()` mid-edit. Debounce writes or use an explicit Save/Apply/on-blur commit.
- **Unvalidated exported broadcast receiver (Lint `UnsafeProtectedBroadcastReceiver`):** [WidgetSystemEventReceiver](file:///c:/Users/kevin/Dev/fillmark/app/src/main/kotlin/com/fillmark/app/widget/WidgetMidnightReceiver.kt#L22-L54) is `exported="true"` for system broadcasts (`DATE_CHANGED`, `TIME_SET`, `TIMEZONE_CHANGED`, `BOOT_COMPLETED`) but never checks `intent?.action` against an explicit allowlist before running work.
- **Onboarding first-frame DataStore race:** [MainActivity.kt](file:///c:/Users/kevin/Dev/fillmark/app/src/main/kotlin/com/fillmark/app/MainActivity.kt#L50-L63) sets `initialValue = UserPreferences(onboardingCompleted = true)` (with `METRIC_ML`), which can briefly pass the wrong `initialUnit` on US locales or flash `MainNavigation` for a frame before `collectAsStateWithLifecycle` receives the real DataStore value. Retain the loaded `prefs` from `preferencesFlow.first()` as the initial state.
- **Onboarding hides Health Connect install prompt on Android 10–13:** [OnboardingScreen.kt](file:///c:/Users/kevin/Dev/fillmark/app/src/main/kotlin/com/fillmark/app/ui/onboarding/OnboardingScreen.kt#L89) only checks `hcManager.isAvailable()`, hiding the card when `SDK_UNAVAILABLE_PROVIDER_UPDATE_REQUIRED` could link users to install Health Connect.
